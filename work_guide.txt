SETUP & TESTING GUIDE
=====================

Prerequisites
-------------
1. MongoDB
   - Option A (Local): Install MongoDB Community and ensure it is running (default port 27017)
   - Option B (Atlas): Create a free cluster at https://cloud.mongodb.com and get your connection string

2. Node.js
   - Install Node.js (v18 or later recommended)


==================================================
PART A — BACKEND SETUP
==================================================

1. Open terminal and navigate to:

   c:\Users\WELCOME\OneDrive\Desktop\Maintenance-Checklist\server

2. Install dependencies:

   npm install

3. Configure environment:

   Edit the .env file and set MONGO_URI to your database connection string.

   Local MongoDB example:
   MONGO_URI=mongodb://localhost:27017/maintenance_checklist_development

   MongoDB Atlas example:
   MONGO_URI=mongodb+srv://<username>:<password>@cluster0.xxxxx.mongodb.net/maintenance_checklist_production?appName=Cluster0

   Other .env settings:
   PORT=5000
   NODE_ENV=development          (use "production" for Atlas)
   JWT_SECRET=change-this-to-a-long-secret
   JWT_EXPIRES_IN=1d
   CLIENT_URL=http://localhost:5173

4. Seed the database with default accounts:

   npm run seed

   This creates the three default accounts defined in src/seed-data.json.
   To add or change seed accounts, edit src/seed-data.json — no code changes needed.

5. Start the backend server:

   Development (auto-restart on file changes):
   npm run dev

   Production:
   npm start

6. Backend runs at:

   http://localhost:5000

PART B — FRONTEND SETUP
==================================================

2. Install dependencies:

3. Configure environment:

4. Start the frontend:

5. Open the application in browser:

   http://localhost:5173

==================================================
PART D — TESTING BY ROLE (UI)
==================================================

--------------------------------------------------
Admin Testing
--------------------------------------------------

1. Log in as Admin (admin@example.com / Admin@123)
2. Create records under each section:
   - Stations  — name and code required
   - Users     — assign role (admin / staff / supervisor); toggle isActive
   - Shifts    — select station, set times, assign staff and supervisors
   - Templates — select station, add checklist items (mandatory flag + input type)
3. View the Reports section for submission status summary

Confirms:
- JWT authentication
- MongoDB CRUD operations
- Role-based access control


--------------------------------------------------
Staff Testing
--------------------------------------------------

1. Log in as Staff (staff@example.com / Staff@123)
2. "Assigned Shifts (Today)" lists shifts assigned to this user for today
3. Click "Open Checklist" on a shift
4. Fill in checklist items (mark mandatory items as completed)
5. Add a staff remark if needed
6. Click "Submit Checklist"

Expected validations:
- Mandatory items left incomplete → submission blocked
- Shift expired (past end time) → submission blocked


--------------------------------------------------
Supervisor Testing
--------------------------------------------------

1. Log in as Supervisor (supervisor@example.com / Supervisor@123)
2. View pending submissions
3. Click Approve or Reject on a submission
4. Add a comment or rejection reason
5. Check submission history

Expected validations:
- Only "submitted" status submissions can be reviewed
- Rejection requires a reason

PART E — API-ONLY TESTING (SWAGGER / POSTMAN)
==================================================

1. Open Swagger:
   http://localhost:5000/api-docs

2. Use POST /auth/login with credentials to get a JWT token

3. Click "Authorize" at the top and enter:
   Bearer <token>

4. Test endpoints:

   Auth:
     GET  /auth/me

   Admin:
     GET/POST        /admin/stations
     PUT/DELETE      /admin/stations/{id}
     GET/POST        /admin/users
     PUT/DELETE      /admin/users/{id}
     GET/POST        /admin/shifts
     PUT/DELETE      /admin/shifts/{id}
     GET/POST        /admin/templates
     PUT/DELETE      /admin/templates/{id}
     GET             /admin/reports/checklists

   Staff:
     GET             /staff/my-shifts/today
     GET             /staff/checklists/{shiftId}
     POST            /staff/checklists/{shiftId}/submit

   Supervisor:
     GET             /supervisor/submissions
     POST            /supervisor/submissions/{id}/approve
     POST            /supervisor/submissions/{id}/reject
     GET             /supervisor/history

Expected:
  - Correct role   → 200 / 201
  - Wrong role     → 403 Forbidden
  - Missing token  → 401 Unauthorized


==================================================
TROUBLESHOOTING
==================================================

1. MongoDB Connection Errors
------------------------------
Possible causes:
- Local MongoDB service not running
- Wrong MONGO_URI in .env
- Atlas IP whitelist does not include your IP
- Wrong Atlas username / password

Fix:
- Local: start the MongoDB service
- Atlas: add your IP in Network Access → Add IP Address

2. "Invalid email or password" on Login
----------------------------------------
Possible causes:
- Seed has not been run yet
- Wrong credentials

Fix:
  cd server
  npm run seed

3. "Your account is inactive" on Login
----------------------------------------
The user exists but isActive is false.
Enable the account in Admin → Users → Edit → Active user checkbox.

4. CORS / Network Errors
--------------------------
Possible causes:
- Backend not running
- Wrong VITE_API_BASE_URL in client/.env
- CLIENT_URL mismatch in server/.env

Expected values (default):
  client/.env  →  VITE_API_BASE_URL=http://localhost:5000/api
  server/.env  →  CLIENT_URL=http://localhost:5173

5. No Shifts Showing for Staff
--------------------------------
Possible causes:
- No shift has been assigned to this staff user for today
- Shift assignment date does not match today's date

Fix:
- Log in as Admin → Shifts → Add New
- Set Assignment Date to today and assign the staff user
